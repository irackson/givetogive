## Secure transfer and private retention

The operator supplies a small strict manifest containing fresh release/readiness assertions and bindings. With Node 24, from `tools/simulation`, use `node --experimental-strip-types src/hosted-community.ts pack`. Its environment is limited to paths `COMMUNITY_MANIFEST_FILE`, exact private `COMMUNITY_ENCRYPTED_OUTPUT=.state/runs/<UUID>/input.g2genc`, and `COMMUNITY_BUNDLE_KEY`. Root arranges secure key transport; never paste keys in commands or logs. Pack reads only, refuses nonempty SQLite WAL and unexpected or linked sidecars, permits only the normal zero/32-KiB SHM lock index, seals the narrowly sanitized credential transport copy and exact original program/journal bytes plus staging protection file, writes a new exclusive ciphertext, and never signs in a member or opens a writable journal.

The input is gzip-compressed then AES-256-GCM authenticated/encrypted with a random 96-bit nonce and 256-bit key. Strict file allowlists, hashes, bounds and linked-path checks precede extraction; recovery-only payloads cannot be used as fresh inputs. Fresh independent DB readiness must attest `noMemberTokens:true`. Pack removes provisioning's unused legacy random `agent.token` placeholders **only from the transport copy**; original credentials and both journal files remain unchanged, IDs/passwords/control token are preserved, and any token field arriving at hosted admission is rejected. After locked installation and the credential-free cache smoke, the broker emits only `awaitingPrivateInput` and waits at most ten minutes with read-only draft asset checks. Root can then freshly inspect the canonical deployment/readiness, pack once and upload the exclusive input. This does not relax the five-minute attestation age at actual admission. An existing stale, malformed or previously consumed input is not replaced, renewed or retried.

**No public Actions artifact, cache, repository file or published release receives private state, even encrypted.** Root separately prepares one dedicated unpublished draft release, exact target SHA, tag `community-acceptance-<UUID>`, and strict JSON association body `{ "protocolVersion": 1, "repository": "irackson/givetogive", "runId": "<UUID>", "headSha": "<SHA>" }`. Root verifies anonymous metadata/asset access is unavailable before use. Its sole input asset is `community-input-<UUID>.g2genc`.

The only configured secret is `COMMUNITY_STAGING_BUNDLE_KEY`. The job's short-lived `GITHUB_TOKEN` has `contents:write` solely for the private recovery/orchestration step; checkout does not persist credentials. Install and credential-free smoke receive no staging secrets. Only the parent broker holds the key/GitHub token, and only its guarded draft GET/asset-upload functions use the token. The existing supervisor and member child receive the existing OS/SIM allowlist, no GitHub key/token, database/Stripe/production/admin credentials or arbitrary runtime injection variables. This is step/process isolation, not a claim that GitHub can grant write permission to only one step.

Draft GET verifies unpublished status, exact release ID/repository/head/run association; anonymous draft/input-asset requests must return 404. Input asset ID, name, size and SHA-256 must survive the second inspection. Downloads never forward authorization to the signed GitHub asset CDN. Uploads accept only encrypted exclusive names, reject existing assets and recheck exact returned asset ID/name/size/digest plus unpublished/anonymous status. No update/delete/tag/publish API is implemented. There is no automatic upload retry after an ambiguous response.

Checkpoint 00 is uploaded and verified **before** member admission; additional encrypted SQLite-backup checkpoints occur at five-minute intervals, then final retention. Fewer than 20 assets are allowed, including input. No plaintext SQLite/WAL files are uploaded. Each SQLite backup is individually consistent; the two live backups are **not one atomic cross-journal checkpoint**. Their recovery-only envelope and `automaticResumeAllowed:false` explicitly prohibit using an older live snapshot to replay actions that may have happened afterward.

## Cancellation, failure and acceptance

SIGINT/SIGTERM, retention failure or an owned paused/ambiguous member stops admission and sends the exact owned supervisor one graceful SIGTERM; its reviewed IPC/shared finalizer drains actual pending work, flushes telemetry and releases ownership only when unambiguous. A one-second observer reads at most 64 KiB of the sanitized supervision stream per tick and recognizes only fixed attention categories/exact actor-line aliases; temporary observation backoff is not mislabeled a halted actor. Malformed/truncated/oversized supervision fails incomplete. Repeated signals do not interrupt an ongoing graceful drain. If the supervisor unexpectedly exits, a fallback may signal its recorded runner only after kernel PID/start-tick/executable/initial-parent proof; otherwise no unknown process is touched. A bounded 120-second graceful wait never force-kills a runner. Interruption truthfully leaves the run paused/incomplete, never an hour pass. Normal duration completes naturally. Root can later perform ordinary authenticated admin Stop/recovery only after job/PID/ownership/journal review; no admin credential or broadened runner scope is added here.

Final encrypted retention is attempted on handled failure. Hard VM death, force cancellation, network failure or GitHub shutdown deadlines can prevent final drain/upload; no claim of guaranteed survival is made. Retain earlier immutable ciphertext checkpoints and hosted histories, review all ambiguities, and never automatically rerun/resume/reconstruct missing actions. An earlier live checkpoint alone cannot authorize continuation.

The summary computes the existing all-user continuity criterion from actual retained action results, not uptime: all 253 warmed up, at least an hour through the least recent participant, no participant gap over 180 seconds and success in each full five-minute window. It also requires real browser mutations and clean local terminal journals. Successful hour computation is **not full acceptance**: independent hosted ownership/drain attestation, the original full-denominator live-feed latency measurement/history navigation, and actual paid-tier/Stripe lifecycle acceptance remain separate. No limits, denominators or financial requirements are waived.

The attention observer also consumes at most 100 new rows per second from the local telemetry journal through SELECT-only, read-only SQLite opens. Actual `action_result` state `paused` for an exact participant detects halted authorization rejections even when sanitized stdout says only `rejected`; ordinary 400/409 conflicts and observation backoff remain nonfatal. Final bounded log/telemetry catch-up and incomplete JSONL-tail rejection prevent a terminal backlog from hiding a halted actor. No existing runner fingerprint file is changed.
